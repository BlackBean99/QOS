# ExecPlan rules

ExecPlan은 긴 작업을 다른 개발자나 Codex가 저장소만 보고 이어갈 수 있게 하는
자기완결적이고 살아 있는 실행 문서다.

## 작성이 필요한 경우

- 두 개 이상의 계층 또는 패키지에 걸친 기능
- DB 스키마, 인증, 전략 DSL, 백테스트 엔진 또는 주문 실행 변경
- 마이그레이션, 대규모 리팩터링, 1시간 이상 예상 작업
- 실패 시 명시적인 복구 절차가 필요한 변경

## 위치와 이름

- `.agent/execplans/NNNN-short-name.md`에 저장한다.
- 번호는 기존 파일의 다음 순번을 사용한다.
- 하나의 논리적 작업마다 하나의 계획을 유지하고 중복 계획을 만들지 않는다.

## 필수 내용

각 계획에는 다음을 포함한다.

- 목적과 사용자가 확인할 수 있는 결과
- 날짜가 있는 상태(`Draft`, `Active`, `Blocked`, `Complete`)
- 현재 구현 상태와 근거 파일
- 범위와 비범위
- 의존 순서가 드러나는 단계와 각 단계의 acceptance criteria
- 실제 명령과 수동 확인을 포함한 검증
- 안전한 롤백 또는 수동 복구 절차
- 날짜가 있는 진행상황 체크리스트
- 작업 중 발견한 사실과 남은 위험
- 결정 로그와 관련 ADR 링크
- 결과 요약(완료 시)

## 유지 규칙

- 계획은 구현 전에 만들고, 사실·범위·명령이 바뀌는 즉시 갱신한다.
- 완료된 일과 예정된 일을 구분한다. 실행하지 않은 검증은 통과로 쓰지 않는다.
- 중요한 선택을 계획에만 묻어두지 말고 ADR로 분리한 뒤 상호 링크한다.
- 단계는 가능한 한 하나의 세션에서 검증할 수 있는 작은 수직 슬라이스로 나눈다.
- 각 단계가 저장소를 일관된 상태로 남기게 하고 위험한 의존성을 먼저 검증한다.
- 토큰, 키, 개인정보, 계좌정보, 대화 전문이나 숨겨진 사고과정을 기록하지 않는다.

## 완료 조건

계획 상태를 `Complete`로 바꾸기 전에 모든 acceptance criteria, 저장소 Definition of
Done, 문서 갱신, diff 리뷰와 사람의 검토가 끝났는지 확인한다. 일부 게이트를 실행할
수 없다면 계획은 그 사실과 위험을 남긴 상태로 유지한다.
